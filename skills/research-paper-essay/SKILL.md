# Research Paper Essay

Turns an existing rigorous research project into a public essay that reads
like a New York Times feature but holds up to the same scrutiny as the
paper it's drawn from — narrative pull, real numbers, honest null results.

## Step 0 — confirm the venue

Confirm where it will run and under whose byline. For a personal
newsletter: no company branding, no CTA — the essay ends on its last real
point. Don't assume; ask if the project's home repo isn't obviously
personal.

## Step 1 — read the primary source, not a summary of it

Find the actual paper/README/results file (not a memory of a past
conversation about it). Pull the exact numbers: sample sizes, z-scores,
correlations, dates, held-out validation results. A number restated from
memory might be wrong — re-verify against the source file immediately
before it goes in a sentence.

## Step 2 — pick ONE narrative spine

A research project usually has several findings. A real magazine feature
picks one and makes the rest texture, not a checklist section-by-section.
The strongest spine is usually the counter-intuitive one: a hypothesis
that looked right and wasn't, an assumption the data quietly overturns, a
result that required getting fooled first before it held up. If several
findings feel equally strong, ask which one before drafting — it changes
the whole shape of the piece.

## Step 3 — the arc

expectation/hypothesis → the build (method explained in plain language,
via metaphor, not jargon) → the illusion or false positive (what looked
true, and why) → the debunking (the actual control/null-model result
that killed it) → what survives (the one thing that holds up under
scrutiny) → the wider turn (what this implies beyond the specific study —
the kicker).

## Step 4 — voice: NYT register, Princeton numbers

- **Pure narrative prose** — no bulleted dossiers, no colored callout
  boxes (that's a different register for a different source type). Numbers live inside sentences: "z = −0.27, indistinguishable
  from noise," not a stat pulled out onto its own line.
- **Translate method, don't summarize it.** Explain a k-nearest-neighbor
  graph or a regression the way you'd explain it to a smart friend, then
  move on — don't strip it out entirely (that's where the rigor lives).
- **Show the false positive.** The moment the researcher got
  fooled by a confound and caught it is more credible than a clean
  success story — it's what separates real methodology from a marketing
  claim.
- **State null/negative results as plainly as positive ones.** "There is
  no global rate" earns the same confident sentence as "detective fiction
  is real." Undercutting the original hypothesis is the whole
  credibility play here.
- **No unexplained acronyms or unlinked claims.** Every number should be
  traceable to the source file; link to the live project/repo once, near
  the end, so readers can verify rather than take it on faith.

## Common mistakes

| Mistake | Fix |
|---|---|
| Covering every finding as its own section | Pick one spine (Step 2); the rest gets a sentence, not a section. |
| Pulling stats into boxed callouts | That's a dossier register. This one keeps numbers in-sentence. |
| Restating a number from memory of a prior conversation | Re-open the source file and re-verify before writing the sentence. |
| Soft-pedaling a null result to make the piece feel more conclusive | State it as confidently as a positive result — the honesty is the credibility. |
| Explaining method so thoroughly it reads like the paper itself | Translate through one clear metaphor, then move the narrative forward. |
